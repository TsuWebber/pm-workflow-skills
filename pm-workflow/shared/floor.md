# PM Floor：所有 pm-* skill 共用的底線

每個 pm-* skill 都要遵守。子指令檔有更明確規定時，以子指令檔為準。

---

## 0. 每次執行先做

1. **讀私人設定**：`~/.claude/pm-config.md`。裡面有規格庫路徑、Git / Jira / Notion 設定、公司專有名詞與部門。
   - 找不到 → 照佔位符原樣執行，不要猜值；在回覆結尾用一句話提醒建立（範本：repo 的 `pm-config.example.md`）。
2. **讀專案背景**：目前工作目錄下的 `.pm/PROJECT.md`（`pm-setup init` 產生）。沒有就照常執行，不捏造背景。
3. **讀子指令檔**：各 skill 的 `reference/<子指令>.md`，用到才讀，讀完整份再照做。
4. **規格庫路徑**：子指令檔裡的 `drafts/`、`specs/`、`archive/` 都以 pm-config 的規格庫路徑為根；git 指令用 `git -C <規格庫路徑> …`，不依賴目前目錄。
5. **寫作規則**：寫任何規格或對外文字時，套用 `shared/writing.md`。
6. **交付前自檢**：產出規格、AC、決策文件、release note 前，用 `pm-review` 的 `reference/review/rules.md` 快速掃一次，有 P0 先修再給。
7. **做完提示下一步**：一句話建議接下來用哪個 skill（見 README 的工作流程），不主動執行。

---

## 1. 語言與用語

- 一律使用繁體中文。
- 專有名詞依 `~/.claude/pm-config.md` 與全域 `CLAUDE.md`。
- 環境名稱固定寫 `ALPHA` / `BETA` / `PRODUCTION`。
- 同一份文件內同一個概念只用一個詞，不混用（例：不要「訂單」「單據」「工單」交替指同一件事）。
- 專案特有名詞以 `.pm/PROJECT.md` 的「名詞補充」為準。

## 2. 外部系統寫入

- **預設只在對話中產出草稿。** Notion、Jira、Confluence 等寫入，只在使用者明確指示時執行（「存到 Notion」「寫進去」「開票」）。
- 一次會動到多個區塊 / 多張票時，寫入前先列出將動到的清單，等使用者再確認一次。
- 寫入完成後回報寫到哪裡（頁面 / 票號 / 連結）。

## 3. 待確認與假設

- 待確認項目統一格式：`- 🟡 待確認：[內容]`
- 放在對應段落或子主題的下方，**不集中到文件最後**。
- 不使用 `TBD`、`**🟡 TBD**` 標題或其他變體。
- 可做最小合理假設，但必須貼近已討論內容，並明確標示是假設。
- 不擴寫使用者沒提過的功能、規則、方案或範圍。

## 4. Emoji

- emoji 只能出現在**各指令模板明定的位置**（例：`pm-launch release` 的區段標題、`🟡 待確認`、`👤` User Story callout）。
- 不自創 emoji 分類標籤，不在一般段落或條列中當裝飾。

## 5. 寫法

- 能一句話說清楚就不展開成一段。
- 沒有內容的段落直接省略，不留空殼。
- 優先描述結果與使用者可見的行為，不描述系統內部流程。
- 同一件事不在兩個地方重複描述。
- 不保留討論語氣、聊天殘留或 `<aside>` 等格式殘留（Explore mode 除外）。

## 6. 可驗證

- **Success Metrics 必備四要素**：現況（baseline）、目標（target）、衡量方式（系統 / dashboard / 公式）、時間範圍。沒有 baseline 時，用「上線後第一個月觀察、第二個月設定目標」兩階段寫法並標示為觀察期。
- **AC 與 release note 保持黑箱**：不寫 API 欄位、資料庫欄位、內部 log；後端正確性從可觀察結果切入。
- 規則要有判準：出現「適當」「視情況」「必要時」「合理」時，必須接著寫判斷條件，否則改成 `🟡 待確認`。

## 7. 空話黑名單

以下詞語單獨出現、後面沒有具體對象或數字時，視為空話，要改寫或刪除：

- 提升使用者體驗、優化流程、提高效率、增加便利性
- 全面、完整、一站式、無縫、賦能、打通
- 「等」結尾的開放式列舉（例：「支援 A、B 等格式」→ 要列完，或註明「本版僅 A、B」）
- 「更好」「更快」「更清楚」而沒有比較基準

## 8. 部門與權責

- 部門職責以全域 `CLAUDE.md` 為準（產品、營運、財務、物流、生管、客服、業務、增長傳播）。
- CLAUDE.md 標為「待確認邊界」的權責（例：BOM 維護在營運還是生管），文件中涉及時一律標 `🟡 待確認`，不自行認定。
