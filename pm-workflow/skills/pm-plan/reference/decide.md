
# decide：決策文件（原 Decision Doc Mode）

## Overview

針對單次重大改動，整理一份簡單乾淨的決策文件（.md），讓相關人能快速看懂「為什麼要改、有哪些選項、建議選哪個」。

- 預設語言：繁體中文
- 預設輸出：在目前工作目錄建立 `.md` 檔，檔名用決策標題（例：`2C銷退流程調整-決策文件.md`）
- 使用者丟資料進來就直接產初稿，不先來回追問

---

## When To Use

- 某個改動影響大、需要跨部門或主管拍板
- 需要比較多個方案並留下決策紀錄

不適用：
- 方向還很模糊、需要邊聊邊收斂 → `pm-plan scope`
- 已決定要做、要寫功能規格 → `pm-spec write`

---

## Template

```markdown
# [決策標題]

> 狀態：討論中 ｜ 日期：YYYY-MM-DD ｜ 相關：[連結]

## 背景
為什麼現在要討論這件事，是什麼觸發的。

## 現況
目前怎麼運作、涉及哪些系統與部門、問題出在哪。

## 問題拆解
- 要解決什麼
- 限制條件
- 這次不處理什麼

## 方案

| | 方案 A | 方案 B |
|---|---|---|
| 做法 | | |
| 優點 | | |
| 缺點 | | |
| 成本／影響 | | |

## 建議
選哪個、為什麼。

## 決議
最後決定、決定者、後續待辦。
```

狀態可用值：`討論中` / `已決議` / `已廢棄`

---

## Writing Rules

- 簡單乾淨：能一句話說完就不要展開，不加多餘段落或裝飾
- 沒內容的段落直接省略，不硬寫
- 方案至少兩個；若使用者只給一個，補上「維持現狀」作為對照
- 方案比較表的列可依情境增減（例如加「可逆性」「上線時程」），但保持精簡
- 「建議」要明確選一個，並說明關鍵理由；不做模稜兩可的結論
- 「決議」段在初稿階段留空或寫「待決議」
- 資訊不足處用 `🟡 待確認：[內容]` 標在對應段落，不集中到最後
- 不自行擴寫使用者沒提到的方案、規則或範圍
- 專有名詞與部門職責依全域 CLAUDE.md 定義（OMS、經銷商平台、2B/2C、營運/財務/物流等）

---

## End Action

輸出檔案後，用一兩句話告知檔案位置與 `🟡 待確認` 的數量。
不主動寫入 Notion 或其他地方，使用者明確要求才做。
