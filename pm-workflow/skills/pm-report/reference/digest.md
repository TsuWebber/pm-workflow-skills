# Change Digest Mode

## Overview

每天早上把 使用者 前一個工作日做過的改動整理成「給專案夥伴看的同步訊息」，一個專案一段，使用者 自己複製貼到對應的 DingTalk 群組。

- 輸出語言：繁體中文
- 輸出位置：對話框（排程觸發時就是排程結果）。**不會自動發到 DingTalk**，目前沒有串接
- 讀者：專案群組裡的夥伴（RD、設計、QA、相關部門），重點是「改了什麼、對他們有什麼影響」，不是 使用者的工作日誌

不適用：
- 要寫自己的 Daily（昨天做了什麼、今天要做什麼）→ `pm-report daily`
- 要給使用單位看的正式上線公告 → `pm-launch release`

## Date Logic

- 「昨天」= 今天往前推**最近一個工作日**（週一 → 上週五），時間範圍 00:00–24:00 Asia/Taipei
- 使用者指定日期就用指定的

## Data Sources

前三個來源只抓 **使用者 本人**做的改動，別人的改動不列。第四個（群組對話）是**選用**來源，有匯出檔才讀。

### 1. spec repo git（spec 檔改動）

- Repo：`<SPEC_REPO_PATH>`（remote 是內部 Gitea）
- 先 `git fetch`，再看 `origin` 預設分支和所有遠端分支：
  `git log --all --since="<昨天> 00:00" --until="<今天> 00:00" --author="<GIT_AUTHOR>" --name-status`
  （`<GIT_AUTHOR>` 換成自己的 git author 名稱，有多個就各加一個 `--author`）
- 專案歸屬看路徑：`drafts/<YYMM>/<專案資料夾>/...`，資料夾名就是專案代號
- 內容摘要看 `git show` 的 diff，抓出**規則、流程、範圍、欄位定義**的變化；錯字、排版、搬段落不列
- fetch 失敗（不在內網）→ 用本機現有的 log，並在該專案段落尾加一行「（spec repo 未同步到最新）」

### 2. Jira 工單

- 站台 `your-team.atlassian.net`，`cloudId` 要先用 `getAccessibleAtlassianResources` 取 GUID，不能直接傳網域
- JQL：`issue in updatedBy(currentUser(), "<昨天>", "<今天>") ORDER BY updated DESC`（日期格式 `YYYY-MM-DD`，不限 project）
- 每張票看昨天 使用者 做了什麼：新開、狀態變更（A → B）、改了描述 / AC、留言、改負責人
- 專案歸屬：看票的 Epic / 父項標題，或 Description 裡的 Notion Spec link，對到專案對照表

### 3. Notion PRD / Spec 頁面

- 專案資料庫：`collection://<NOTION_DB_ID>`，`PM` 欄位包含 使用者（user id `<NOTION_ID>`）的案子
- 對每個案子的 Spec 頁面 `fetch`，看 `last_edited_time` 是否落在昨天；是的話才算有改
- Notion API 拿不到逐字差異，改動內容依序從以下來源判斷，**都沒有就不要猜**：
  1. 同一份 spec 在 spec repo 有對應 commit → 以 git diff 為準（不要重複列兩次）
  2. 頁面內的 Changelog / 版本紀錄區塊
  3. 昨天新增的留言（`notion-get-comments`）
  4. 以上都沒有 → 只寫「PRD 有更新」並加 `🟡 待確認：改了哪些段落`

### 4. DingTalk 群組對話（選用）

用途跟前三個不同：不是找 使用者的改動，而是找**昨天群組裡已經討論出的結論、還沒回的問題**，讓早上的訊息能收斂討論、補上該回的事。

- 資料夾：`<DINGTALK_EXPORT_DIR>/groups/`，一個群組一份 JSON（格式同 `pm-launch retro` 用的匯出：`group`、`messages[]`，訊息有 `sender_name`、`created_at` 毫秒時間戳、`content_text` / `content_json`、`is_recall`）
- **這個 skill 不負責匯出**，也不要自己去讀或解密 DingTalk 的本機資料庫。匯出由 使用者 手動用夥伴的 DingTalk 匯出工具產生後放進上面的資料夾
- 資料夾不存在或沒有檔案 → 跳過這個來源，只在給 使用者的提示段寫一句「沒有群組匯出檔，群組討論未納入」
- 有檔案時先檢查覆蓋範圍：檔案裡最晚一則訊息早於「昨天」→ 該群組不讀，提示段寫「[群組] 匯出停在 MM/DD，未納入」
- 已知限制：匯出工具只讀主資料庫，最新幾小時的訊息可能還沒寫進去，所以昨天傍晚以後的對話可能缺漏；有缺漏疑慮時在提示段註明，不要當成「昨天沒討論」
- 解析：用 Python 或 PowerShell `ConvertFrom-Json` 讀 JSON，`created_at` 轉 Asia/Taipei，只留昨天 00:00–24:00、`is_recall = false`、有文字內容的訊息；圖片標 `[圖片]`
- 從對話裡抓三種東西：
  1. **結論 / 決定**：有人拍板、多人同意、或 使用者 確認過的事
  2. **待回覆**：@使用者 或明顯在問 PM 的問題，使用者 昨天之後沒有回
  3. **新需求 / 範圍變動**：有人提出要加、要改的東西
- 閒聊、貼圖、單純「收到」「好」不列
- 群組歸屬看專案對照表的「DingTalk 群組」欄（比對 JSON 的 `group` 名稱）

## 專案對照表

同一個專案在各來源的名字不一樣，用這張表合併。對不到的歸到「其他」段落，並在結尾提示使用者補表。

| 專案（群組訊息標題） | spec repo 資料夾 | Notion 專案 Name | Jira Epic / 關鍵字 | DingTalk 群組 |
|---|---|---|---|---|
| 月結訂單 | `monthly-billing-orders` | 🟡 待補 | 🟡 待補 | 🟡 待補 |
| 2C 銷退優化 | `2c-sales-return-optimization` | 🟡 待補 | 🟡 待補 | 🟡 待補 |

- 使用者告訴你新的對應關係時，直接更新這張表
- 找不到對應時可以先用名稱相似度猜，但要在該段落標 `🟡 待確認：專案歸屬`

## Output Format（DingTalk 純文字）

規則跟 `pm-report daily` 一樣：不能用 markdown 粗體、斜體、checkbox，標題用全形括號。

每個有改動的專案輸出一段，段落之間用一行 `────────` 分隔，方便分別複製：

```
📢 [專案名稱] 昨日更新｜MM/DD(週X)

【規格】
・[改了什麼規則 / 範圍]，影響：[誰要注意什麼]

【工單】
・PROJ-101 [票名]：To Do → In Progress
・PROJ-102 [票名]：新開，[一句話說明]

【昨日討論結論】
・[結論一句話]（[誰] 確認）

【請協助】
・@[角色] [具體要對方做的事]
```

規則：
1. 沒有內容的區塊整段省略；整個專案昨天沒改動就不輸出那段
2. 每條一句話，寫「結果」和「影響」，不寫系統內部過程（例：寫「退貨單可部分退款」，不寫「新增 refund_partial 欄位」）
3. 【規格】優先寫會改變別人工作的東西（規則改了、範圍加減、AC 變動）；純補充說明、文字修飾不列
4. 【請協助】只有真的需要對方動作時才寫；不知道要 @ 誰就寫角色（RD / 設計 / QA / 營運…），不要猜人名
5. 同一件事在 git 和 Notion 都有，只寫一次，放在【規格】
6. 資訊不足用 `🟡 待確認：` 標在該條下方，**貼到群組前由 使用者 自己刪掉或補完**
7. 全部專案都沒改動 → 只回一句「昨天（MM/DD）沒有需要同步的改動」
8. 群組裡的結論如果已經反映在 spec 或工單改動裡，寫在【規格】/【工單】那條就好，不在【昨日討論結論】重複
9. 群組裡的結論**還沒**反映到 spec / 工單 → 照列在【昨日討論結論】，並在給 使用者的提示段提醒「這條還沒補回 spec」

所有段落之後，另起一段**給 使用者 本人看**（不要貼群組）：
- 群組裡還沒回覆的問題（誰、問什麼、哪個群），讓 使用者 回覆時可以順便在訊息裡回答
- 群組結論還沒補回 spec / 工單的項目
- 對不到專案的改動
- 抓取失敗的來源（例：Jira 驗證失敗、spec repo fetch 失敗）
- `🟡 待確認` 的總數

## Workflow

1. 算出「昨天」日期
2. 四個來源各自抓昨天的資料（可以平行；群組對話沒有匯出檔就跳過），任何一個失敗或過期都不要中斷，記下來放到結尾提示
3. 用專案對照表把改動歸到專案，去掉重複
4. 依 Output Format 輸出草稿
5. **不要寫入或發送到任何外部系統**（DingTalk、Notion、Jira 都不動）。使用者要求修改就直接改草稿

## Notes

- 這些規則是初版，使用者之後調整格式或範圍時，以最新的話為準並更新本檔
- 每天早上 8:30（平日）有排程 `morning-change-digest` 自動跑這個 skill
- 待補：專案對照表各欄；群組匯出若之後能自動化，再把「先匯出」加進 Workflow 第 2 步
- 專有名詞（OMS、經銷商平台、2B/2C…）與部門職責依全域 `CLAUDE.md`
