# consistency：全文掃矛盾

## 檢查項目

大改落檔後主動提議；使用者說「掃一下」時執行。

1. 讀整份 SPEC（spec repo：含 drafts 與尚未合併的 PR）
2. 逐項檢查：
   - 前後規則衝突（增補的段落 vs 原段落）
   - AC 與內文不一致；AC 編號是否連續
   - 公式：是否完整、邊界條件（> vs ≥、含不含 0）
   - 狀態流轉：哪些狀態可取消／可編輯，前後說法是否一致
   - 適用範圍：銷售 vs 銷退、彈窗 vs 詳情、月結 vs 非月結、2C vs 2B
   - 名詞：同一概念是否出現兩種叫法
   - 編號引用：是否都附中文名、指向的章節是否存在
3. 輸出清單（不改檔）：

```
[章節（中文名）]
- 問題：……
- 建議：……
- 嚴重度：🔴 會做錯／🟡 措辭
```

4. 有需要決定的，用選擇題問；使用者說 GO 才修
