# harden：補邊界、例外與逆向流程

PRD 通常把正向流程寫清楚，卻漏掉「出錯、取消、退回、資料不對、量很大」時怎麼辦。
這個指令逐項掃過，把漏掉的情境找出來，補成 spec 內容或 `🟡 待確認`。

輸入：Notion URL、本機檔案，或對話中的 spec 內容。可指定只看某個 A-x。

---

## 檢查面向

依功能性質挑相關面向，不相關的直接跳過，不硬湊。

| 面向 | 要問的問題 |
|---|---|
| **狀態** | 有哪些狀態？每個狀態可以轉到哪些狀態？不允許的轉換會怎樣？空狀態、loading、錯誤狀態怎麼呈現？ |
| **逆向流程** | 取消、退貨、部分退、換貨、作廢、撤回、重送時怎麼處理？已經往下游送出的資料要不要回沖？ |
| **權限與角色** | 誰能看、誰能改、誰能審核？權限不足時看到什麼？同一筆資料兩個人同時改？ |
| **資料異常** | 必填缺漏、格式錯誤、重複資料、主檔不存在（商品下架、BOM 不完整、客戶停用）時怎麼辦？ |
| **數量與上限** | 0 筆、1 筆、上限筆數、超過上限？大量資料時分頁 / 匯出 / 效能？列表或圖表內容溢出可視範圍時怎麼呈現？ |
| **金額** | 含稅 / 未稅、折扣、運費、組合商品拆分（BOM 分攤）、四捨五入、幣別、負數？ |
| **時間** | 截止時間、排程執行時點、跨日 / 跨月、時區、生效日 vs 建立日、補跑？ |
| **跨系統** | 涉及 OMS / 經銷商平台 / ERP / 品牌官網 / 第三方渠道 / 庫存工具 / CDP 時：哪邊是資料來源、同步時機、同步失敗怎麼辦、兩邊不一致以誰為準？ |
| **既有資料** | 上線前已存在的舊單 / 舊資料適用新規則嗎？需要資料轉換嗎？誰負責？ |
| **環境與上線** | ALPHA / BETA / PRODUCTION 需要不同設定嗎？需要 feature flag 或分批上線嗎？回滾怎麼處理？ |
| **通知** | 誰需要被通知？失敗時誰會知道？ |

---

## Workflow

1. 讀 `.pm/PROJECT.md`（若有），確認涉及系統與上下游，作為「跨系統」面向的依據。
2. 逐個 A-x 套用相關面向，找出 spec 沒寫到的情境。
3. 每個缺口判斷屬於哪一類：
   - **可合理推定**：依既有規則可推出答案 → 直接寫成建議補上的 behavior bullet，標明「建議」。
   - **需要決策**：涉及商業規則、帳務、跨部門作業 → 寫成 `🟡 待確認`，並註明該問誰（依 CLAUDE.md 部門職責）。
4. 依下方格式輸出。

---

## Output Format

```
## Harden：[文件名稱]

掃描範圍：A-0 ~ A-4 ｜ 找到缺口 N 個（建議補充 X、待確認 Y）

### A-2 [功能名稱]

**逆向流程**
- 建議補充：訂單取消後，已預扣的庫存於 OMS 立即釋放
- 🟡 待確認：部分退貨時，組合商品是否可拆單退？（問：營運、財務）

**跨系統**
- 🟡 待確認：OMS 傳送 ERP 失敗時是否自動重送？重送幾次？失敗通知誰？（問：工程）

---

### A-3 …
```

規則：
- 依 A-x 分組，組內依面向分小段（粗體段首，不用 H3）。
- 沒有缺口的 A-x 不列。
- 使用者確認後，可直接把結果合併進 spec 對應 A-x 的子主題下方；寫回 Notion 需另外明確指示。
- 不擴寫新功能；只補「既有功能在非正常情境下的行為」。
