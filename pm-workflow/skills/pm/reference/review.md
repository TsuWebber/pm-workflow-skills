# review：審查文件（規則＋讀者）

一次跑完兩段審查，合併成一份依嚴重度排序的問題清單。
可審規格庫的 `spec.md`、決策文件、release note、Notion 頁面，或對話中貼上的內容。

| 段 | 看什麼 | 規則檔 |
|---|---|---|
| 第一段：規則 | 格式與底線規則有沒有違反（可逐條對照、可重複） | `reference/review/rules.md`（原 audit） |
| 第二段：讀者 | 工程、QA、設計、營運、財務等讀者讀完能不能做事 | `reference/review/readers.md`（原 critique） |

使用者只要其中一段時（例如「只檢查格式」「只看讀者會不會卡」），只跑那一段。

---

## Workflow

1. 讀 `.pm/PROJECT.md`（若有）。
2. 讀 `review/rules.md`，照它的規則逐條檢查，記下違規。
3. 讀 `review/readers.md`，挑 3–4 個讀者角色從頭讀一次，記下讀完仍無法做事的地方。
4. 合併兩段：同一個位置、同一件事只列一次；讀者問題依影響換算嚴重度（會做錯 = P0、會來回確認 = P1、讀起來吃力 = P2）。
5. 依下方格式輸出。問使用者要不要直接修正；修正版先給在對話中，寫回檔案或 Notion 仍要另外明確指示。

---

## Output Format

```
## Review：[文件名稱]

**一句話總評**：[目前最大的問題]
結果：P0 × N ｜ P1 × N ｜ P2 × N

### 最需要先處理的 3 件事
1. **[問題]**（P0｜影響：工程、QA｜來源：規則 S-01 / 讀者）
   - 位置：
   - 為什麼是問題：
   - 建議修法：

### 其他問題
| 嚴重度 | 位置 | 問題 | 建議修法 | 來源 |
|---|---|---|---|---|

### 寫得好的地方
- （1–2 點）

### 規則通過
G-04、G-06 …（只列編號）
```

規則：
- 「最需要先處理」最多 3 件，強迫排序。
- 沒有問題的區塊整段省略。
- 建議修法要具體到可以直接改，不寫「請補充」。
- 結尾一句話建議下一步：問題多屬邊界 → `harden`；屬跨部門 → `impact`；屬用語 → `clarify`。
